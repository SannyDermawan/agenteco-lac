# Life After Code: post-code automation for AgentEco

Submission for the GitLab Transcend "Life After Code" hackathon, Path B ("Bring Your Own"), Supervised autonomy.

- Original open source project (MIT): https://github.com/SannyDermawan/agenteco-multichain
- This GitLab project: https://gitlab.com/agenteco-group/agenteco-lac
- Baseline tag for "what existed before": `pre-lac` (commit `172edc3`, 17 Oct 2026, 150 commits since 24 Sep 2026)

## The problem

AgentEco is built by one person. Writing the code (contracts, SDK, backend, website) is the part that got faster with AI. Everything after the code stayed manual: running three test suites by hand, reading diffs alone, checking for leaked keys, remembering to look at the deployment. The repository had no CI of any kind. For a project that holds escrowed funds (test funds today), that is the risky part.

## What was added (all new work, after 5 Oct 2026)

| Stage | What runs | Where |
|---|---|---|
| plan | Issue and merge request templates, a Duo triage flow that labels and summarises new issues | `.gitlab/issue_templates/`, `.gitlab/duo/flows/issue-triage.yaml` |
| create | Duo reviewer flows for TypeScript and for Solidity contracts, CODEOWNERS | `.gitlab/duo/flows/`, `.gitlab/CODEOWNERS` |
| verify | Foundry build and tests, SDK, backend and CLI typecheck and tests, frontend lint and production build | `.gitlab-ci.yml` stage `verify` |
| package | SDK and CLI tarballs, contract ABIs | stage `package` |
| secure | SAST, secret detection and dependency scanning (GitLab templates), a findings summary, a Duo flow that explains findings and proposes fixes | stages `test` and `secure`, `scripts/ci/security-summary.mjs` |
| release | Public status site on GitLab Pages from the default branch; a manual Cloud Run deploy for approval-gated releases | job `pages`, job `release:cloud-run`, `deploy/cloud-run/` |
| configure | Environment contract: every service documents its variables and no example holds a secret | `scripts/ci/check-env.mjs` |
| monitor | Health checks of the API and the website after each deploy and on a schedule; a failure opens an incident issue | `scripts/ci/health-check.mjs` |
| govern | License check of 1,187 locked packages, repository policy rules (nine checks) | `scripts/ci/license-check.mjs`, `scripts/ci/policy-check.mjs` |

## Before and after

| Before | After |
|---|---|
| No CI. Tests run by hand before a release | Every push and merge request runs all suites |
| One maintainer reading diffs alone | Duo flows review every merge request; a human approves |
| Leaked keys or risky dependencies found by luck | Scanners on every pipeline, findings explained in plain language |
| Outages noticed when a user complains | Scheduled checks open an incident issue |
| The state of the project lives in the maintainer's head | A public status page generated from each pipeline |

## What existed before the hackathon

The whole AgentEco product: escrow v3 and the arbiter council (Solidity), the Solana program, the SDK, CLI, backend, keeper, host and AI arbiter, the website, and deployments on test networks. History from the first commit (24 Sep 2026) is preserved in this repository.

## Honest status

- All networks AgentEco runs on are test networks. No real funds.
- The pipeline jobs were developed and run locally first (Foundry, SDK, backend and CLI suites all green, frontend production build). GitLab pipeline runs and Duo flow runs are linked from the status site once they exist.
- Five lint errors in existing frontend code are reported rather than fixed, see `docs/KNOWN-ISSUES.md`.
- Duo flows follow the public schema; tool names still have to be confirmed in the Flow Builder, see `.gitlab/duo/README.md`.

## How to run it

Everything is in `.gitlab-ci.yml`. To reproduce locally: `forge test`, `npm ci && npm test` inside `agent-runtime/` and `backend/`, `npm run build` inside `frontend/`, and `node scripts/ci/policy-check.mjs`.

## Submission text (draft)

AgentEco lets AI agents hire each other with escrow, disputes and onchain reputation. We built it fast with AI help, but the work after the code was still manual and the repo had no CI. For Life After Code we automated that half with GitLab: a nine-stage pipeline (tests for contracts, SDK, backend, CLI and frontend; packaging; security scanning; license and policy checks; Pages deploy; health monitoring with incident issues) and four GitLab Duo flows that review merge requests, review contract changes with a security lens, explain scanner findings and triage issues. A human approves cloud releases (Supervised autonomy). A public status page is generated by each pipeline.
